# 中英混打意圖實驗 v2：目標與比較設計

狀態：目標與判定設計，尚未執行。本階段交付實驗設計；產品整合仍依事先固定的品質證據決定。這不是已完成實驗或可直接開跑的 evaluator 契約。先確定要回答的問題；待局部策略、測試工具與資料取得程序各自固定後，才進行品質評測。v1 的規格、資料與負結果保留，不覆寫。

## 1. 唯一主問題

**在中文模式開啟中英混打時，僅在中文與英數解釋衝突的地方，更積極採用成立的中文組字，能否改善英文後接中文與誤按後的恢復，同時辨認真正的英數混合、帳號、型號及作者原本要保留的情況？**

這次研究的是局部意圖判斷，不是重新設計整個輸入法或所有中文解碼。不能只證明能找到中文字，也不能只證明更少改成中文：兩邊都要測對。最終目標是減少使用者回頭修正的需要。

預先區分三個問題，不以其中一個冒充另外兩個：

1. **改善是否存在：** 原本英文後中文第一字錯切、數字注音被當數字、一次誤按吞掉後續中文，能修好多少？
2. **代價是什麼：** 真正的英文、英數、帳號、版本等，多少被錯切成中文或被借走字尾？
3. **資訊何時足夠：** 第一字時是否可判；若不足，後續一字／詞出現後能否恢復？不能用後來才知道的字提前評分。

## 2. 意圖與輸出的定義

意圖標籤從任務指定的欲輸出內容及來源取得，先於任何策略結果。不能因為 dictionary 有字、baseline 怎麼切、某模型分數較高，就替輸入貼上中文或英數標籤。

策略需要判斷的是哪些 spans 應組中文、哪些應保留原鍵；帳號、型號等是保留行為的子類，不要求額外建一個帳號語意分類器。每次介入另記使用了哪些既有 guard／中文證據，供分析成敗。

| 意圖／約束 | 正確行為 | 主要觀察 |
| --- | --- | --- |
| 英文後接中文 | 保留完整英文前段，將後段轉成指定中文讀音／可接受字詞 | 第一中文字起點、完整讀音、最終輸出 |
| 誤按後恢復中文 | 誤按那段保留可還原的原鍵，後續正確中文正常組字 | 從第一個正確音節起，有多少音節被吞成 literal、何時恢復 |
| 真正英文／英數混合 | 整個指定 literal span 原樣保留 | 英文字尾是否被借走，數字、大小寫與標點是否改寫 |
| 作者保留情況 | 指定帳號、型號、版本、日期等及明確使用者選擇依原意保留 | 保留正確率、與既有各 guard 的關係 |
| 一般正常中文 | 沿用既有中文組字 | 逐事件退步與最終結果，作不可退步對照 |

原鍵例子不直接等於唯一意圖。`microsoft593` 可以是「microsoft窄」或完整帳號；兩種都要有任務標籤與案例。`593` 已在目前版修好，屬 mandatory 回歸，不拿它重複計算成新修復成效。

### 無法從輸入分辨的情況也要算

相同可觀測前文、設定、原鍵與事件若對應兩種意圖，確定性策略在該時刻必然顯示同一結果。不能要求它在資訊相同時同時猜對，也不能把這些難例全部排除以提高正確率。

- 保留相反意圖的任務列，放在同一 equivalence group／同一 split；不得把意圖或預期答案傳給策略。
- 分別記第一聲調、下一完整音節／詞及 Enter 前的判斷。兩種輸入後續分岔後，才可要求使用新證據區分；只重播當時可見的 prefix。
- 完全相同的完整觀測仍有兩種意圖時，列為「不可辨識衝突」，報兩邊命中／損失、候選可還原性及該測試分布的最高可能命中率；不改標籤為任意答案皆正確。
- 主表同時報包含衝突的各意圖成績與可辨識子集；全體不因 ambiguous 改名而消失。歧義組的兩種意圖先等權計分，另報不同中文意圖占比下的取捨，不能宣稱是自然使用者頻率。
- 若目標只能靠偏好中文交換掉同鍵帳號意圖，就明列為積極／保守模式取捨，不聲稱能自動辨認兩者。候選保留不等於 top-one 判對。

## 3. 對照與允許變因

| 對照 | 固定版本／用途 |
| --- | --- |
| U：作者上游 | `v0.2.7` = `04fa94ee0d6e74c03f5a9e829180680c2032f6e9`，量測相對作者原設計的修復與代價 |
| C：目前保守模式 | preview2 `e754019571573051d8c29e06526802c31d5172e2`，量測既有修復但未積極組字的行為 |
| A：目前積極模式 | 同一 preview2，只切換 aggressive，判斷我們已做的積極策略實際效果 |
| E：局部修正版 | 以同一 preview2 為底，只改歧義切點的取捨；必須先另行固定可列舉的分支差異 |

先用同一資料比較 U/C/A，回答現有積極修正是否已幫助主目標、在哪些作者保留情況付出代價。這項比較本身就是研究問題，不預設必須有新模型。

E 只能調整英文／中文衝突及 failed-composition 後恢復的局部判斷；正常 decoder、同音選字、學習、鍵盤 layout、標點、數字格式、原鍵選取、設定 UI 與提交方式不重寫。直接中文不交給一個新的全域分類器重判。合法但低頻的中文、純數字注音與英文尾字競爭必須進測試，不因難判而改成全部保留 literal。

作者規則要分兩種：

- **硬約束：** 英文模式、明確選原鍵／手選鎖定、私密／停用等狀態及明確自訂詞的既有保護。E 不繞過；個別 API 是否能看見欄位要有來源依據。
- **待評估啟發式：** 數字尾碼、罕用字、未知英文前綴、完整英文字、型號格式等對意圖的猜測。不能全部強制 literal 後宣稱解決中文問題；也不能移除後宣稱中文分數提高即成功。逐規則報中文修復與 literal 誤傷。

`kevin87`、`nina87`、`lisa0304`、`gpt4`、`h264`、`gpt4o`、`hello4`、`zoom3`、`hello2.4` 等指定 literal 任務是必要保留案例。現有 aggressive tests 中 `gpt4→gp斥` 等輸出是目前行為紀錄，不是新的正確意圖標籤。需要同時檢查「能不能組」及「此處應不應組」。

來源核對：已讀 `v0.2.7:core/session/mixed.go` 的 `finishMixedTone`／`mixedBoundary`／`englishThenNumber` 相關規則，以及該版 `core/session/mixed_english_boundary_test.go` 的保留案例；目前模式對照見 `core/session/mixed_policy_test.go`。這是來源核對，尚未在新資料重播 U/C/A。

**每次只測一項改動。** 先測不增加新窗口的局部中文取捨；如後續詞證據不足，再另立對照測延後決定／恢復。候選保留、窗口長度、margin、訓練器不在同一 E 一起更換。若需要訓練，先做單獨 fitting protocol，不能先假定線性或神經模型是答案。

Neighbor、fuzzy、autocomplete 與 neural rerank 第一輪關閉，避免將按鍵替換、同音字與混打意圖混成同一結果。誤按組只測錯誤之後的恢復；修正誤按本字另立研究。

## 4. 資料要圍繞主問題

先固定來源、取得預算、標註方法與 split，再看策略輸出。v1 及既有測試中已看過的案例全作開發／回歸，不計入新 held-out 成效。公開型號可以當負例，但不能讓大量同廠商變體主導結果。

正式新 test 的最低目標：

- **400 個獨立中文意圖 groups：** 已知英文前綴、未知／大寫前綴、數字鍵起始中文、誤按後恢復各100個 primary 任務；一個 group 只預先指定一個主類。交叉特徵另記 metadata。
- **400 個獨立 literal 意圖 groups：** 一般英文、帳號／合成密碼、型號、版本、小數／日期／時間、URL／路徑、底線／大小寫識別字、外觀像中文按鍵的隨機英數，各50個 primary 任務。
- **100 個獨立一般中文 groups** 作不可退步對照；硬約束／手選／原鍵／提交另有固定完整事件案例。
- 另建立上述意圖碰撞的 paired 任務，包含「前綴相同、後續不同」與「完整觀測相同」兩種；配對不能拆 split，不能用大量複本充獨立樣本。主隊列若含碰撞照常計分，額外挑選的碰撞挑戰組另報，不改主分母。

數量只是資格，不保證門檻通過。每個來源／詞原型／前綴／模板／可觀測上下文之相依關係先定義及做 transitive grouping；不足就回報不足，不拆 family、換 seed 或看過結果才補到過關。400不是400種字串變體。合成密碼不使用真實憑證。

每列保留欲輸出的 literal／中文 spans、可接受讀音／字面、意圖來源、keyboard layout、逐鍵 events、完整 prelude、詞彙設定及各 checkpoint。保留原作者測試的既有特例，另新增未見原型；不能只從詞庫抽中文字再拼英文、以「可組字」當作意圖的全部證據。

## 5. 指標與預定成敗

以下先固定為正式判斷要求，後續執行契約只能使分母與計算更明確，不能在讀取新 held-out 後放寬。任何尚未明確的策略、分組或事件計算必須在開跑前解決。

| 目標 | 要報的證據 | 通過要求 |
| --- | --- | --- |
| 英文後中文恢復 | 同組 U/C/A/E 的第一中文切點與完整讀音錯誤；修好／變壞配對數 | 相對 C 的主中文錯誤下降至少30%，且相對 A 不增加；各主類不得淨退步 |
| 誤按不吞後文 | failed span 後的正確中文讀音、連續被吞音節數、恢復所需音節 | 誤按組相對 C 錯誤下降至少30%，且相對 A 不增加；修復不靠改寫誤按原鍵 |
| 真正 literal 保留 | 任一 checkpoint 曾把 intended literal 自動轉成中文的 group incidence；最終保留另報 | 點估及 Wilson two-sided95上限均≤1%；必要作者保留案例全過 |
| 已有正常行為 | 直接中文逐事件對照、模式、手選、原鍵與提交 | 正常中文及硬約束零新增退步；Enter=完整最後顯示，零掉鍵／重複／越鎖改動 |
| 能否及時區分 | 第一聲調／下一完整音節／Enter 前的分類、恢復與 ownership；同觀測碰撞表 | 最終錯誤不能被「有候選」掩蓋；有區別的後續證據出現後須納入上述品質分母；不可辨識衝突單列取捨 |

C 基線某項零錯誤時要求 E 也零錯誤，不宣稱有可量測改善。若 A 已達成目標而 E 沒有增益，結論可以是保留現有積極策略，不為了有新實作強行替換。字面同音選字錯誤與意圖／讀音錯誤分開，但完整字面結果仍需提供，不報只有切點的成功。

各主類等權報告，另報逐 group 主成績與 variants worst case；不以單一混合總分掩蓋某類失敗。報所有計數、分母與95%區間；字面 gold 缺失、ownership unsupported、分母0均 unavailable，不填零。罕見字、單音節與多音節詞的成績分開，確認是否只有看到完整詞才有效。

上一輪「兩次 tone opportunity」與≤1% unnecessary revision 不直接當成本輪核心假說。這輪先不新增窗口；如另測可恢復窗口，其穩定性與明確事件定義須在該實驗前固定，不能因本輪結果調整後沿用同一 test。

## 6. 順序與解釋規則

1. 完成本文件的目標設計。先列原作者保留規則、衝突任務與每個 baseline 的來源，不寫全域替代 parser。
2. 另行固定 E 的最小差異及全部可見輸入；定義資料來源／預算／intent gold／families／split。先有純回歸與 development 隊列，正式 test 保留未見。
3. 先驗證工具完整重播前文到 Enter 的 composition，U/C/A observer parity、ownership、privacy、字面與原鍵；v1 context 缺口未補好前不跑品質。策略不得拿 fixture 指定的正確中文切點當自己的 run 起點。
4. 固定新資料、程式與報表 hash，才跑 U/C/A/E 配對；若有 train/dev 選擇，所有規則先固定且 final test 只用一次。不得先跑品質才決定哪些案例算介入範圍。
5. 若中文改善且 literal／保留／正常中文皆達標，才支持局部積極修正。只改善中文但誤傷 literal，結論是取捨未解；不能稱自動意圖判斷成功。
6. 若候選包含正解但選錯，檢討局部意圖訊號；若正解不在候選，才研究保留／窗口；若只有不可辨識衝突失敗，說明模式偏好或額外訊號的必要性。不能將整套失敗直接歸因於單一因素。
7. 資料／工具不合格則證據不足；有效品質未達門檻則不整合。修改方法需新版本與新的未見 test。通過後仍另做 live integration／Windows 原生與效能驗證，再決定測試包。

本次只交付目標設計；尚未收新資料、修改產品、訓練或評測。先前的失敗原型不構成本核心想法已被否定的證據。
