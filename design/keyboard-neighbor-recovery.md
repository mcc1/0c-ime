# 鄰鍵容錯：設計與第一版

## 問題與範圍

使用者以兩隻食指打字時，可能按到目標鍵旁邊的鍵。按鍵組不成注音或詞庫讀音時，混打會把它留成英數，或把尾端切成另一個中文字。這和「發音相近」不同：ㄨ 的 j 誤按成 k，是鍵盤位置造成的 ㄜ，不是模糊音配對。

本 PR 疊在 `fix/mixed-digit-rarity` 的已試用版本上，獨立新增鄰鍵恢復。它不改保守／積極取捨，不更新安裝包、字典、模型或平台外殼。這不是整句拼字校正，也不保證能辨認所有誤按。

第一版只處理 **QWERTY 實體鍵盤、標準注音、積極中英混打**。功能有獨立開關 `neighbor-key-recovery`，預設關閉。不打聲調、一般注音模式、倚天、許氏及其他實體鍵盤配置不在這版範圍內。現在的 `keyboard-layout` 是注音符號映射，不代表已經偵測到使用者的實體鍵盤。

## 觸發順序

1. 沿用現有的明確選擇、自訂英文詞、數字寫法、完整讀音、輕聲退回與英文單字保留。
2. 完整讀音失敗時，鄰鍵搜尋只看 2 或 3 個按鍵的音節，且至少含一個字母；長串前段必須恰好是已知英文單字。
3. 只替換其中一個按鍵為實體鄰鍵。聲調鍵保持使用者所打的聲調，且必須是明確聲調；空白不觸發。
4. 修正後須遵守注音順序，沒有同類符號覆蓋，且在詞庫有完整單字讀音。只符合更長詞頭不夠。
5. 沒有鄰鍵讀音時，繼續原本的英中邊界推斷。找到鄰鍵讀音時，優先於「把不認識的英文字尾切成中文字」這種退路。

完整音節本來就可組字時不修正。數字、標點、已選回原文、自訂英文詞、英文字本身均有原有保留規則；鄰鍵搜尋不能改動其前段。純數字不搜尋鄰鍵。

積極混打本身仍可能轉換帳號／型號，這個 PR 不改它的既有取捨。新的開關也不是英數識別器：已知英文單字後若接了一段像錯誤注音的識別碼，仍可能與恢復中文衝突。需要逐鍵保持原文時切英文模式。

## 鄰鍵、假設與排序

`core/layout/AdjacentKeys` 只描述實體 QWERTY 的位置，以四分之一鍵寬表示各列交錯。同行只看左右相鄰鍵，跨行只看相鄰列且水平距離不超過四分之三鍵寬；不包含空白、修飾鍵或 Shift 產生的字元。產生的替代鍵再交給目前的注音映射解讀，沒有另建一份硬編碼的注音鄰近表。

第一版只容許一次替換，不插字、不刪字、不交換、不更改聲調、不跨越兩個錯鍵。兩種尾端長度最多檢查約 30 個單鍵假設，無搜尋整句或無限回溯。相同讀音去重，不將不同錯鍵路徑當成多份語言證據。

- **只有一個可用讀音：** 自動收成該讀音，再由現有字詞解碼與神經重排決定同音字。唯一讀音不等於已知使用者意圖，故仍可選回原按鍵。
- **多個讀音：** 不自動猜定，原按鍵仍顯示在組字區。按 ↓ 後列出鄰鍵候選，每讀音最多 3 字、合計最多 8 字，附「鄰鍵＋建議按鍵」提示。候選依既有統計分數及已輸入的左側中文排序；同分使用固定列舉順序。
- **沒有結果：** 原有混打流程接手。

現有神經模型比較的是同讀音候選，沒有受訓來直接比較不同按鍵／讀音切法。本版不把不同讀音的神經分數當成可比較的信心，也沒有宣稱用神經網路判定中文／英文。多義修正先由使用者選擇；後續若要依語境自動挑不同讀音，需要另外評測門檻與退步率。

## 可撤回與狀態

自動修正仍用 `mixedKeys` 保存**真正按下的鍵**。在修正字上按 ↓，第一頁保留原按鍵候選，選回時不建立中文字偏好。多義待選時，原按鍵固定在候選第一項，Enter 送出畫面原文，不暗中接受候選。

`neighborKeys` 只在記憶體標記尚未確認的自動修正位置，隨插入、刪除、還原與重設一起移動或消失；不寫入個人詞庫。自動修正經過的詞段不自動學習。使用者明確選了中文字後，才以修正後的正確讀音進入原有學習；選回原按鍵不學習。

私人／敏感請求、暫停及本機模型封鎖狀態不啟用鄰鍵搜尋。使用原有核心協定與候選附註欄位，不加輸入紀錄、不新增網路呼叫，不依賴修改 TSF、Fcitx5 或 IBus 外殼。

## 驗證與評估

以下案例需以原有功能開關與鄰鍵開關分別測試，不更改原有帳號規則的預期輸出：

| 按鍵／操作 | 鄰鍵關閉 | 鄰鍵開啟 |
| --- | --- | --- |
| `ki3` | 原按鍵 | 自動恢復 `ji3` 的「我」；可選回 `ki3` |
| `helloki3cl3` | 可能切成 `hellok`＋其他漢字＋好 | `hello我好` |
| `qji3` | 可能切出尾端的其他漢字 | 原按鍵，↓ 可選鄰鍵讀音；Enter 不接受猜測 |
| `qji3cl3` 不開選字直接續打 | 原邊界推斷 | 保留 `qji3`，後面的「好」繼續組字 |
| `593`、`microsoft593fmp6` | 既有積極混打結果 | 同左 |
| `kevin87`、`gpt4`、`3.4`、`10:30` | 既有積極混打結果 | 同左，不代表積極模式會保留所有帳號 |

測試涵蓋：幾何鄰接及對稱性、唯一／多義讀音、原按鍵還原、確認後學習、未確認不學習、插入刪除後來源位置、功能關閉／保守／英文／敏感／暫停／其他排列、設定持久化及未來值保留、新 session 設定隔離、引擎重啟載入及舊引擎設定契約。

正式字典驗證可重現，不讀個人資料、不下載資料、不安裝到桌面：

```sh
ZC_TEST_PUBLIC_DICTIONARY="$PWD/assets/data" go test ./internal/datadir -run TestNeighborRecoveryWithPublishedDictionary -v
```

只有上述公開案例的功能驗證，尚不是人類誤按語料的準確率。沒有量測真實食指輸入的修正召回率／誤改率；不能據此把預設改成開啟，或允許更多鍵更動。

## 試用方式

從這個 PR 建置的程式才有新開關。無須替換已安裝版本，可先用隔離 CLI 試用：

```sh
go run ./cmd/0c-cli -data assets/data -mixed-input -mixed-input-policy aggressive -neighbor-key-recovery
```

互動操作與逐鍵重播沿用 CLI 的說明；錄製檔需使用相同開關重播。整合此 PR 的桌面版本會在「中英切換」顯示「鄰鍵容錯（試用）」。內建輸入習慣要先複製成自訂，開啟中英混打並選積極；鄰鍵開關可獨立開關，切回保守會停用但保留設定。

第一版未涵蓋：實體 Dvorak／Colemak、自訂鍵盤座標、其他注音排列、無聲調、聲調誤按、多鍵誤按、原本已能組字的錯字、未知英文前段後的錯鍵修正，以及多義失敗音節已照原文保留後再回頭修正的完整介面。這些應用實際可公開的誤按案例另行設計，不藉此放寬既有帳號規則。
